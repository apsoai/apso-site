# infra: apso.ai on Cloudflare (Pulumi)

Spec: mavric/apso-site#28. This Pulumi TypeScript program owns everything around the site. The site code is built by `@opennextjs/cloudflare` and deployed by wrangler, through Workers Builds or `npm run cf:deploy`.

| Resource | Where |
| --- | --- |
| `apso.ai` zone (protected from delete) | `index.ts` |
| Every non-site DNS record from Route 53 | `dns-records.ts`, generated by `scripts/export-route53.sh` |
| The `apso-site` Worker (no code), its workers.dev URL and preview URLs (public, by Matt's decision 2026-10-24) | `index.ts` |
| Worker secrets `GHL_API_TOKEN`, `GHL_LOCATION_ID`, `RESEND_API_KEY`, `CONTACT_TO_EMAIL` | `index.ts`, through `wrangler secret bulk` (see below) |
| Custom domain `apso.ai`, and `www.apso.ai` 301 to the apex | `index.ts`, only when `serveApex` is true |

Worker secrets go through wrangler because the Cloudflare provider (v6) can only set secrets on a script that it uploads itself, and wrangler uploads this one. The values reach wrangler on stdin and are stored encrypted in Pulumi state. Secrets persist across `wrangler deploy`.

`NEXT_PUBLIC_*` values are inlined at build time, so they are Workers Builds build variables, not Worker secrets.

## Secrets

All values come from 1Password through `scripts/with-secrets.sh`. Pulumi needs both env files:

```bash
export SECRETS_ENV="deploy/secrets.env deploy/infra-secrets.env"
```

`deploy/infra-secrets.env` adds one item in the `apso-site` vault: `cloudflare-api-token`, field `credential`. Scope it to the apso.ai zone (Zone, DNS, Rulesets and Workers Routes edit) and the account (Workers Scripts edit).

Without the token, `pulumi preview` stops with one line naming the missing variable.

## State and secrets provider

State lives in S3 bucket `apso-site-pulumi-state`, and state secrets are encrypted with KMS alias `apso-site-pulumi`, both in AWS account 105223538344 (profile `mavric`). `Pulumi.yaml` pins the backend, so commands in `infra/` use it without changing your global `pulumi login`. The stack was created with:

```bash
cd infra && npm ci
pulumi login 's3://apso-site-pulumi-state?region=us-east-1&awssdk=v2&profile=mavric'   # optional: Pulumi.yaml already sets it
pulumi stack init prod --secrets-provider 'awskms://alias/apso-site-pulumi?region=us-east-1&awssdk=v2&profile=mavric'
pulumi config set apso-site:accountId 7c0690992acb27aed18a97de0fe6a290
pulumi config set apso-site:workersDevSubdomain matt-c06
```

`Pulumi.prod.yaml` holds that config plus the KMS-wrapped data key. No passphrase is involved.

## Phase 1: spike on workers.dev, no DNS change

Local, on the Workers runtime (port 3050):

```bash
npm run cf:build
scripts/with-secrets.sh npm run cf:preview
```

Workers Builds is not covered by the provider. Set it once in the dashboard, after `pulumi up` has created the Worker (Workers & Pages > apso-site > Settings > Build):

- Git repository: `mavric/apso-site`, production branch `main`
- Build command: `npx opennextjs-cloudflare build`
- Deploy command: `npx opennextjs-cloudflare deploy`
- Non-production branch deploy command: `npx opennextjs-cloudflare upload` (preview URL per PR, commented on the PR)
- Root directory: `/`
- Build variables: `NEXT_PUBLIC_POSTHOG_KEY`, `NEXT_PUBLIC_POSTHOG_HOST`, `NEXT_PUBLIC_GTM_ID`, `NEXT_PUBLIC_GA_ID`, `NEXT_PUBLIC_META_PIXEL_ID`, `NEXT_PUBLIC_PRIVACY_V2` (only the ones in use)

## Phase 2: everything except the cutover

```bash
cd infra
../scripts/with-secrets.sh pulumi preview   # full plan
../scripts/with-secrets.sh pulumi up
```

This creates the zone (pending until the name servers move), the DNS records, the Worker and its secrets. `serveApex` stays `false`, so apso.ai keeps resolving through Route 53 to Amplify. Output `nameServers` lists the Cloudflare name servers for phase 3.

## Phase 3: DNS move (Matt approves the moment)

```bash
infra/scripts/export-route53.sh        # re-export; read-only. Commit any diff in dns-records.ts.
cd infra && ../scripts/with-secrets.sh pulumi up
# Diff every record: no output except the site records means ready.
CF_NS=<one of the nameServers outputs>
grep -oE '"(name|type)": "[^"]+"' dns-records.ts | cut -d'"' -f4 | paste - - | sort -u | while read n t; do
  diff <(dig +short "$t" "$n" @ns-622.awsdns-13.net | sort) <(dig +short "$t" "$n" @"$CF_NS" | sort) >/dev/null || echo "DIFF $t $n"
done
pulumi config set apso-site:serveApex true && ../scripts/with-secrets.sh pulumi up
```

Then Matt switches the name servers at Namecheap to the two in `nameServers`. Check mail both ways, the site on apso.ai and www, and HTTPS. Keep the Route 53 zone and Amplify app for 14 days.

## Regenerating DNS records

`scripts/export-route53.sh` finds the zone in AWS profile `apso-live`, then `apso`, then `mavric` (where it lives today), checks that the zone's name servers match the live delegation, and rewrites `dns-records.ts`. It skips NS, SOA and the site records (A/AAAA/CNAME on apex and www).
